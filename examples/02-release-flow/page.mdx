# Test a release pull request.

The smoke test creates an isolated emulator, seeds a repository, changes a package version, opens a PR, merges it, and verifies the merged manifest. It exits when verification finishes.

## Run the scenario

<CodeGroup label="Run the release smoke test">
<CodeTab label="Defaults">

```sh
npm run docker:test
```

</CodeTab>
<CodeTab label="Custom version">

```sh
NEW_VERSION=2.0.0 UPDATE_PR_BODY=1 npm run docker:test
```

</CodeTab>
</CodeGroup>

The smoke-test container is separate from the persistent emulator. A successful run exits with code 0. Commits are made before opening the PR because the pinned emulator snapshots the head commit when it creates the PR.

## Provide GitHub to a workflow

The action supplies a mock GitHub service. The calling workflow provides its own
fixtures and release steps; the action does not run this smoke-test scenario.

```yaml
jobs:
  release-test:
    runs-on: ubuntu-latest
    steps:
      - uses: moyarich/github_emulator@main
        id: emulator
      - name: Create a release in the mock service
        env:
          API: ${{ steps.emulator.outputs.api-url }}
          GH_TOKEN: ${{ steps.emulator.outputs.token }}
          GH_ENTERPRISE_TOKEN: ${{ steps.emulator.outputs.token }}
          REPO: ${{ steps.emulator.outputs.repository }}
        run: |
          gh api "$API/repos/$REPO/releases" --method POST \
            -f tag_name=v1.0.0 -f name='Test release'
```

Pin a version or commit SHA for reproducibility. The mock service is available to
later steps in the same job and is automatically removed in the action's post step.
Existing workflows must use the mock API through their supported client settings.
